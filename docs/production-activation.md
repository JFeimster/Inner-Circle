## Controlled review-branch publication

The workflow is configured for pushes to `phase-2-supabase-hardening` and manual dispatch. After explicit authorization to publish, run `git push -u origin phase-2-supabase-hardening`; this push initiates the first database verification run. Check `gh run list --repo JFeimster/Inner-Circle --branch phase-2-supabase-hardening --workflow database-verification.yml` and inspect the run in GitHub Actions. Confirm its PostgreSQL summary reports one or more tests passed, zero failed, and zero skipped. GitHub requires a workflow file on the default branch for `workflow_dispatch`; therefore `gh workflow run database-verification.yml --ref phase-2-supabase-hardening` is available only after that requirement is met. Do not merge until the run passes and the preview is reviewed.

The connected Vercel project has a READY production deployment from `main`; `vercel.json` contains no rule that disables Git deployments. [Vercel's Git behavior](https://vercel.com/docs/git) normally creates a Preview deployment on a non-production branch push and a Production deployment on a push or merge to the production branch. Thus the review-branch push may create a Preview deployment before the database workflow completes. The actual Preview configuration for this unpublished branch is unverified. Review its environment variables and access protection before authorizing the push. No Vercel deployment settings were changed.
