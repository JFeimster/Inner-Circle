# Production activation runbook

1. Review the local diff on `phase-2-supabase-hardening`; run `npx --yes bun@1.4.5 install --frozen-lockfile`, `npm run lint`, `npm test`, and `npm run build`.
2. Start local Supabase, apply `20261125000100_init_inner_circle.sql`, `20261125000200_atomic_credits_and_invitations.sql`, then `20261125000300_phase3_hardening.sql` in filename order to the local database. In PowerShell run `$env:LOCAL_PG_TEST_URL='postgresql://postgres:postgres@127.0.0.1:54322/postgres'; npx tsx --test tests/postgres.integration.ts`, then `Remove-Item Env:\LOCAL_PG_TEST_URL`. The test refuses non-loopback hosts.
3. Confirm the target Supabase project reference is **`thdnmgmojhhhtjlhbwvn`**, not the unrelated platform-core project. Back up the dedicated project and inspect its current schema. Before applying Phase 3, check `SELECT COUNT(*) FROM public.usage_ledger WHERE status = 'committed'` if the base tables exist. Prior live purchases and usage need a manual balance review because the old ledger did not record pack allocation. Apply the three migration files in filename order only where absent, using the Supabase migration workflow or SQL Editor for that project. Do not run them against another project.
4. Verify `agent_accounts`, `invitations`, `usage_ledger`, `billing_events`, and `rate_limit_buckets` exist; inspect `pg_policies` and `information_schema.role_table_grants` for active-only browser SELECT and server-only writes/RPC execution. Provision the initial verified administrator using the audited procedure in `docs/security.md`.
5. Set `SUPABASE_URL` and `VITE_SUPABASE_URL` to `https://thdnmgmojhhhtjlhbwvn.supabase.co`; set the publishable browser key and server-only `SUPABASE_SECRET_KEY` (or legacy service role fallback). Set `APP_URL` to the deployed app origin. Keep `AI_STUDIO_LIVE_ENABLED=false`, `GEMINI_API_KEY` unset, and `BILLING_WEBHOOK_SECRET` unset during review.
6. After separate approval, configure trusted preview hostnames with `VITE_ALLOWED_HOSTS`, deploy, and verify `/api/health`, email sign-in, invitation redemption, active membership enforcement, and admin operations. Live AI and billing require their own approval, credentials, and end-to-end verification.

No production database or external infrastructure is changed by these repository steps alone.
